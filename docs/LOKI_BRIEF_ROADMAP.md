# Loki Brief Roadmap

- **P1 — Native product foundation.** Sealed at `agent-loki-v1-native-product-contract-foundation-gate`.
- **P2 — Feed briefing and Ollama.** Sealed at `agent-loki-v1-p2-feed-ollama-briefing-core-gate`.
- **P3 — Slack PKCE selected-channel connector.** Sealed at `agent-loki-v1-p3-slack-pkce-selected-channel-connector-gate`; live Slack authorization remains external-configuration-dependent.
- **P4 — Loki Vault archive, multi-account and resumable backfill.** Sealed at `agent-loki-v1-p4-vault-local-archive-multi-account-backfill-gate`: local SQLite archive, provider-neutral account/control contracts, fail-closed entitlement-gated manual resumable Slack backfill, feed reconciliation, local search, retention, storage reporting, and deterministic export. Live Slack proof remains external-configuration-dependent.
- **P5 — Scheduled sync, daily delivery, notifications, and launch at login.** Implemented by the `agent-loki-v1-p5-scheduled-sync-daily-delivery-gate`: one main-app actor scheduler, bounded forward sync, deterministic delivery, privacy-aware local notifications, run history, missed-run recovery, and optional `SMAppService.mainApp` registration. No helper process exists.
- **P6 — Free early-access release hardening and private direct distribution.** Paused before the final seal. The approved icon, early-access production policy, release-safe UI/docs, signing profile, packaging work, and accepted notarized artifact remain private engineering evidence. The accepted artifact is superseded by the user-visible local-date defect and must not be published or used for a public or private release. P6R does not authorize a final P6 tag, a GitHub release, public publication, or a replacement artifact/notarization submission.
- **P6R — Local-calendar date correction and product-scope checkpoint.** Sealed at `agent-loki-v1-p6r-local-date-product-scope-checkpoint`: every user-facing briefing day resolves through the user's local calendar and time zone, absolute event/audit timestamps remain intact, deterministic local-day behavior and migration are covered, and the deferred product scope is recorded. P6R did not seal or resume the full P6 release.
- **P6U — Secure self-update foundation.** Implemented and live-proofed as one bounded private gate. Sparkle 2.9.4 is pinned through Swift Package Manager; App Sandbox, Developer ID, Hardened Runtime, outgoing-network and app-specific Keychain boundaries remain intact; Sparkle's bundled Installer XPC service is enabled while Downloader is disabled; provider-neutral stable/beta/internal policy keeps stable fail-closed; automatic checking remains opt-in; and HTTPS EdDSA-signed full archives exclude DSA, deltas, tokens, and external release-note downloads. Disposable 1.0.0/build 1 to 1.0.1/build 2 proof covered hostile signatures/content, channel/version rejection, safe install readiness, real replacement/relaunch, preservation, and recovery. P6U seals only through the prescribed private commit/tag and does not publish a production appcast/artifact, create a release, or resume P6.
- **P7/P7R — Agent Loki Chat and model capability system.** Sealed at `agent-loki-v1-p7r-agent-chat-model-capability-recovery`; P7R preserves live V8, startup synchronization, Today, preferred local-model readiness, prompt containment, and closed read-only tools.
- **P8 — Multimodal reasoning, semantic retrieval, and research foundation.** The bounded source gate adds explicit primary/text-fallback/vision/embedding/brief-summary roles; active Gemma 3 policy migration; assessed Gemma 4 multimodal recommendation; GPT-OSS primary and model-specific reasoning support; private thinking/content/tool transport; local image-file input; a rebuildable qwen3-embedding semantic index; a disabled-by-default Ollama web-research provider; and an inert connector-ingestion envelope. It does not pull models, capture the screen, authenticate connectors, backfill account history, install/sign/launch P8, or release. The prescribed local seal is `agent-loki-v1-p8-multimodal-reasoning-semantic-research-gate`.
- **P8E — Qwen embedding stability reconciliation.** Sealed at `agent-loki-v1-p8e-qwen-embedding-stability-reconciliation-gate`: canonical request/runtime identity, bounded Float32 numerical variance, retrieval-ranking stability, fatal runtime invalidation, and semantic-generation runtime-profile binding are deterministic and privacy-safe. It did not create or activate a production semantic generation.
- **P8F — Semantic source-authority repair.** The bounded source-only repair separates Index Build Source Authority from Search Result Filters and future Connector Ingestion Authority; requires an explicit nonempty closed source allowlist; gives excluded adapters zero calls and zero reads; binds each generation to its allowlist hash; blocks unknown, changed, revoked, or violated scopes from every retrieval mode; preserves the prior valid generation atomically; and exposes distinct Index Sources and Search Filters. First use selects no build sources, Slack and Vault default off, and the next live activation may select only briefs, schedules, and final Chat messages. Connector authentication/backfill, app lifecycle work, production indexing, signing, installation, and release remain outside P8F. The prescribed local seal is `agent-loki-v1-p8f-semantic-source-authority-repair-gate`.

## Successor gates after P8F

The successors below remain in exact order and are not implemented, activated,
or authorized by P8F.

1. **P9 — Workbench journal, goals, projects, and tasks.** Chat history and the derived semantic index are not a journal, task system, or silently inferred durable memory.
2. **P10 — Authenticated account connectors and history backfill.** The P8 `ConnectorRecordEnvelope` is only an ingestion contract; native Discord, Google, GitHub, Microsoft, Meta, and other login/pull flows remain separate read-authority gates.
3. **P11 — Verified external write actions.** Posting, reply, email, calendar mutation, Slack write, remote deletion, or another external mutation requires explicit preview, approval, authorization, and durable verification evidence.
4. **P12 — Commercial tier.** Billing, subscriptions, licensing, commercial entitlements, and packaging remain deferred.

Signing/installing a P8/P8F app, resuming P6 release work, publishing an update
host, creating a public launch, or beginning P9–P12 requires separate
authorization. Any optional external reasoning or control authority also
requires its own gate.
